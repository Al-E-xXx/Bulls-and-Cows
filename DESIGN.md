# Bulls and Cows — архитектура

RS School «Быки и коровы»: игра без бэкенда, TypeScript + ES-модули в браузере
без бандлера, функциональный стиль, строгий TDD (266 тестов в 8 файлах).

## 1. Общие принципы

Три уровня с направлением зависимостей только «вниз»:

```
index.html → dist/main.js (main.ts — контроллер, единственный источник мутаций UI)
   ├─ src/ui/       — компоненты на DOM API (el(), без innerHTML), эффектов нет внутри
   ├─ src/game/     — чистое ядро: без DOM, без localStorage, без Date.now()
   └─ src/storage/  — тонкий адаптер ключ-значение (инжектируемый KeyValueStore)
```

Правила, которым следует весь код:

- **Чистые функции в ядре.** Любая неопределённость (случайность, время, хранилище)
  приходит параметром: `random: () => number` в `generateSecret`,
  `now: TimeMs` в `registerAttempt`/`elapsedMs`, `store: KeyValueStore`
  в `loadRecords`/`saveRecords`. Это же делает ядро тривиально тестируемым.
- **Иммутабельность обновлений.** Единственная мутабельная переменная приложения —
  `gameState` в `src/main.ts`; каждое событие создаёт новый объект
  (`registerAttempt`: spread + `[...history, entry]`; `addRecord`:
  `[...records, record]`).
- **Компоненты UI не хранят состояние** — они строительный материал экрана;
  состояние живёт только в контроллере, смена состояния = полный ре-рендер
  (`render()` → `clearNode(main)`).

## 3. Алгоритмы и сложность

Обозначения: `n` — длина кода (2–6), `b` — основание (2–16).
Константа `maxCodeLengthForBase = min(6, base)` гарантирует `n ≤ b`, поэтому
все оценки параметрические, а фактически ограничены `n, b ≤ 16`.

### 3.1 `generateSecret` — `src/game/secret.ts`

Рекурсия `pickDigits`: на каждом шаге выбирается равномерный индекс из пула
оставшихся символов (`Math.floor(random() * poolSize)` с clamp), выбранный
символ удаляется из копии пула (`[...pool.slice(0, i), ...pool.slice(i + 1)]`).

- **Время: O(n · b)** — глубина рекурсии `n`, на каждом уровне копирование пула
  размера ≤ b. При `b ≤ 16` это ~100 элементарных операций.
- **Память: O(n · b)** — по копии пула на кадр рекурсии.
- **Корректность распределения:** каждый символ выбирается равномерно из ещё
  не занятых, поэтому каждая перестановка длины `n` равновероятна —
  это частичный Fisher–Yates без мутаций. `random` — параметр, тесты фиксируют
  последовательность.

### 3.2 `evaluateGuess` — `src/game/evaluate.ts`

`bulls` — один pass попозиционного сравнения; `cows = shared − bulls`, где
`shared` — сколько символов догадки встречаются в секрете.

- **Время: O(n²)** — bulls за O(n); для cows каждый из `n` символов ищется
  в секрете (`includes` за O(n)).
- **Память: O(n)** — массивы/итераторы `Array.from`.
- **Обоснование:** при `n ≤ 6` квадратичность несущественна, а вариант «в лоб»
  читается прямо из правила игры. Асимптотически эквивалентная альтернатива
  (`Set` из секрета, O(n)) отклонена как избыточная: символы уникальны, множество
  из ≤ 6 элементов не даёт выигрыша, но добавляет слой опосредования.
  Формула `cows = shared − bulls` верна именно благодаря уникальности символов.

### 3.3 `countPossibleSecrets` — `src/game/counting.ts`

Число кодов — размещения без повторений `P(b, n) = b · (b−1) · … · (b−n+1)`,
рекурсия `countPermutations(length, base) = base * f(length−1, base−1)`
с базой `f(0, ·) = 1` и `f(l, b) = 0` при `l > b`.

- **Первый вызов: O(n)** умножений, **повторные: O(1)** — меморизация
  (`cache: Map<string, number>`, ключ `` `${length}:${base}` ``): модульный
  замыкающий кэш, всего возможных состояний ≤ 6 · 4, то есть кэш ограничен константой.
- **Память: O(n·b)** в худшем случае заполнения кэша, фактически ≤ 24 записи.
- **Обоснование:** функция вызывается экраном настроек на каждую смену длины/базы
  (показать «N вариантов») — меморизация убирает пересчёт, а рекурсия с мемосохранением
  демонстрирует декомпозицию: `P(b,n) = b · P(b−1, n−1)`.

### 3.4 `addRecord` — `src/game/records.ts`

Слияние новой записи с таблицей, сортировка `attempts ↑, затем timeMs ↑`,
обрезка до `MAX_RECORDS = 10`.

- **Время: O(k log k)**, где `k ≤ 11` (10 + новая) — `sort` по копии массива.
- **Память: O(k)** — копия `[...records, record]`, исходный массив не мутируется.
- **Обоснование:** размер таблицы ограничен константой _до_ сортировки, поэтому
  вставка рекорда имеет O(1) верхнюю оценку относительно размера истории игры —
  ни одна структура посложнее (куча, вставка в отсортированный массив) не
  оправдана. Обрезка «наихудшего» элемента после полной сортировки — самая
  простая схема, дающая ровно нужный инвариант: в таблице 10 лучших.

### 3.5 Валидаторы — `src/game/validate.ts`

- `createDigitValidator(base)` — **каррирование**: конфигурация (срез алфавита)
  один раз, дальше предикат символа за **O(b)** (`includes` по алфавиту ≤ 16,
  с нормализацией регистра). Переиспользуется UI-фильтром ввода
  (`sanitizeGuess`, `src/ui/game.ts`) посимвольно.
- `isValidGuess` — **O(n · b)**: маппинг каждого символа валидатором + проверка
  `Set` на уникальность. Контракт намеренно не учитывает `maxCodeLengthForBase`
  (см. §6, решение R5).

## 4. Потоки данных

**Раунд:** `handlePlay` → `startRound(settings, generateSecret(length, base,
Math.random), Date.now())` → `GameState('playing')` → `render()`.
**Попытка:** input-фильтр (`sanitizeGuess`) → `isValidGuess` + антидубликат →
`handleGuess` → `registerAttempt(state, guess, evaluateGuess(secret, guess),
Date.now())` → новый state → `render()`; при `bulls === length` state становится
`won` (с `finishedAt`) ровно в одном месте — в ядре.
**Рекорд:** только при переходе в `won`: `load → addRecord → save` для своей
пары (`persistWinRecord`, `src/main.ts`).
**Таймер:** `elapsedMs(startedAt, now)` чистая; ticking — `setInterval` внутри
компонента, само снимающийся, когда секция detached (`document.contains`).

## 6. История решений

- **R1. Vitest вместо Jest** — нативная поддержка ESM/TS без конфига, `npm test`
  = `vitest run` (`passWithNoTests: true` — тесты коммитятся раньше реализации).
- **R2. Без бандлера** — `tsc` компилирует `src/` → `dist/` как ES-модули,
  `index.html` грузит `dist/main.js` с `type="module"`; из этого следует
  обязательное расширение `.js` в value-импортах исходников (type-only импорты
  стираются компилятором).
- **R3. TypeScript закреплён на 6.0.3** — typescript-eslint на момент подключения
  поддерживал `< 6.1.0`; ESLint 10 (flat config) требует override
  `minimatch ^11.0.5`.
- **R4. `Code` — alias строки, а не массив символов** — канон (нижний регистр,
  уникальность) инкапсулирован в валидаторе; сравнения и дубли дешёвые;
  leading zero не тонет (массив цифр потребовал бы числа/символов с шумом).
- **R5. `isValidGuess` не знает про `maxCodeLengthForBase`** — её контракт из ТЗ:
  «символы допустимы, уникальны, длина полная». Ограничение длины по основанию —
  игра-level: enforced в UI (кламп длины, `clampLength` + пересборка radios
  в `src/ui/settings.ts`), иначе ядро перестало бы быть переносимым.
- **R6. evaluate O(n²) вместо Set** — см. §3.2.
- **R7. `generateSecret` рекурсивный с копированием пула, а не полный Fisher–Yates
  по алфавиту** — меньше состояний под рекурсией, равномерность очевидна;
  стоимость O(n·b) при b ≤ 16 нерелевантна.
- **R8. UI: полный ре-рендер по смене `gameState`** — состояние маленькое,
  дифить DOM дороже, чем перестроить ≤ десятки узлов; экран настроек стейтфулен
  только внутри замыкания (`current: RoundSettings`) и размонтируется на время
  раунда — это и есть «настройки заблокированы после старта».
- **R9. Таблица рекордов разделена на уровне ключа хранилища** (по одной таблице
  на пару) — вместо фильтрации общего массива: меньше данных на чтение, отсутствие
  перекосов топ-10 между режимами, сортировка/обрезка — целиком в ядре (R §3.4).
- **R10. Игровой экран при `won` не рендерит форму попыток** (баннер результата
  - кнопка «Новая игра») — невозможность хода обеспечена отсутствием ввода в DOM,
    плюс defense-in-depth guard в `handleGuess`.
- **R11. Husky:** `pre-commit` — только lint-staged (быстрые фиксация),
  `pre-push` — полный `npm test` (длинное — перед отправкой).

## 7. Интерфейс пользователя (кратко)

Экраны генерируются кодом: настройки (длина 2–6 с клампом по базе, 4 системы
счисления, счётчик вариантов) → игра (условия, таймер, поле ввода с фильтрацией,
ошибки невалидного/повторного ввода, история, «Новая игра») → таблица рекордов
текущей пары (top-10, сортировка попытки↑/время↑). «Новая игра» — возврат в `idle`
без перезагрузки страницы, с сохранением настроек и рекордов.
Адаптивность: карточки + `@media (max-width: 30rem)`.

## 8. Как запустить

```bash
npm install
npm run build   # tsc: src/ → dist/ (ES-модули)
```

Дальше — любой статический сервер в корне проекта (ES-модули не работают по
`file://`), например `npx http-server .` или `python3 -m http.server`, и открыть
`index.html`.

```bash
npm test                     # vitest run — 266 тестов
npm run lint                 # eslint .
npm run format               # prettier --write .
npm run format:check         # проверка форматирования
```
